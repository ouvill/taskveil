# DST-safe civil day boundaries

## 1. 背景とコンテキスト

Homeの端末ローカル日境界は、ローカル0時へ固定24時間の
`Duration(days: 1)`を加えて翌日を求めている。DST開始日はcivil dayが23時間、
DST終了日は25時間になるため、この計算では翌日0時ではなく01:00または23:00を
境界として渡し、due、scheduled、completedの半開区間判定が誤る。

Calendarは年・月・日フィールドから翌日を構成しているが、Homeとは別実装である。
`docs/03_技術仕様書.md`とtask-104が定めるviewer timezone由来のcivil-date /
instant境界契約へ統一する。

## 3. ゴール

- Home / Today / Calendarの日境界を同じcivil-day helperから構成する。
- DST開始日と終了日でも、翌civil dayのローカル0時を半開区間の終端にする。
- 月末・年末の繰り上がりとdue / scheduled / completedの終端除外を回帰testで固定する。

## 7. 制約・注意事項

- `Duration(days: 1)`をcivil dayの代用にしない。
- 各境界は同じ元civil dateのyear / month / dayへoffsetを加えて構成し、固定時間を連鎖加算しない。
- named timezoneを使うtestでは、そのlocationを`toLocal()`でhost timezoneへ失わない。
- Home storageの半開区間契約とactive dueを全件取得する既存設計は変更しない。
- 実装者は独立検証の合否を記入せず、front matterを`done`にしない。
