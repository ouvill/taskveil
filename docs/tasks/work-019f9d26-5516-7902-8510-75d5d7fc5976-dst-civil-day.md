# DST-safe civil day boundaries

## 1. 背景とコンテキスト

Homeの端末ローカル日境界は、ローカル0時へ固定24時間の
`Duration(days: 1)`を加えて翌日を求めている。DST開始日はcivil dayが23時間、
DST終了日は25時間になるため、この計算では翌日0時ではなく01:00または23:00を
境界として渡し、due、scheduled、completedの半開区間判定が誤る。

Calendarは年・月・日フィールドから翌日を構成しているが、Homeとは別実装である。
`docs/03_技術仕様書.md`とtask-104が定めるviewer timezone由来のcivil-date /
instant境界契約へ統一する。

## 3. ゴール

- Home / Today / Calendarの日境界を同じcivil-day helperから構成する。
- DST開始日と終了日でも、翌civil dayのローカル0時を半開区間の終端にする。
- 月末・年末の繰り上がりとdue / scheduled / completedの終端除外を回帰testで固定する。

## 4. スコープ

### やること

- timezoneを明示したtest入力を保持できるcivil-day helperをDart coreへ追加する。
- Home、Today互換helper、Calendarの日・週・月の日付計算を共通helperへ移す。
- Fake bridgeのHome completed判定をproduction SQLと同じstatus別条件へ修正する。
- DST 23時間 / 25時間、月末、年末、半開区間のfocused testを追加する。

### やらないこと

- Rust storage query、client API、FRB API、生成物、DB schema、sync protocolの変更。
- timezone packageを含む依存の追加・更新。
- UI文言、ARB、画面デザインの変更。
- 保存済みdueやscheduledのデータ形式変更。

## 5. 実装手順

1. viewer-localまたは明示されたnamed timezoneのcivil dateから、任意の日offsetの
   ローカル0時を構成するhelperを追加する。
2. Home / Todayの0、1、2日境界を元のcivil dateから独立して構成する。
3. Calendarの日、週、月、date-only変換を同じhelperへ統合する。
4. Fake bridgeのactive / closed Home target条件をproduction SQLへ一致させる。
5. 境界値test、静的解析、Flutter focused test、共通境界checkを実行する。
6. 実装非担当者が統合HEADを独立検証する。

## 7. 制約・注意事項

- `Duration(days: 1)`をcivil dayの代用にしない。
- 各境界は同じ元civil dateのyear / month / dayへoffsetを加えて構成し、固定時間を連鎖加算しない。
- named timezoneを使うtestでは、そのlocationを`toLocal()`でhost timezoneへ失わない。
- Home storageの半開区間契約とactive dueを全件取得する既存設計は変更しない。
- 実装者は独立検証の合否を記入せず、front matterを`done`にしない。
