# Typed sync readiness and atomic account restore

## 1. 背景とコンテキスト

GitHub Issue #54では、同期開始前のaccount runtime、credential、local crypto、
manifest keyの解決失敗が、logged-outと同じ成功no-opへ変換される問題を扱う。
profile coordination公開候補PR #72のhead `0739f2f`でprofile guard、runtime epoch、
sync leaseは導入されたが、readinessは依然`Option<ActiveSyncContext>`であり、
credential欠落とaccount-bound crypto欠落を区別しない。

session復元も、credential generationをcache済みとして公開してからidentity settingを
読み、local crypto bindingとのuser / tenant / device一致を検証していない。
途中失敗がfalse logged-out stateを残すため、profile guardとepoch refresh後に全入力を
検証し、remote session runtimeを1回のatomic publicationで更新する。一方、
ADR-013に従いlocal crypto復元はremote credential検証から分離し、credential破損や
secret store障害だけでaccount-bound offline mutationを停止させない。

## 3. ゴール

- 同期readinessを`LoggedOut`、`Ready`、`CredentialUnavailable`、
  `AccountBoundUnavailable`、`Err(ClientError)`として型で区別する。
- DB、secret store、credential、crypto corruptionを成功no-opへ変換しない。
- session identityとlocal crypto bindingを検証してからremote session runtimeを
  atomicに公開し、local crypto runtimeはremote credentialから独立して復元する。
- #55のprofile busy / lease / stale epochと既存upgrade、clock skew分類を失わない。

## 4. スコープ

### やること

- `taskveil-client`へaccount / sync readinessのtyped contractを追加する。
- profile guardとruntime epoch refresh後にcredentialとcryptoを一度だけ解決する。
- active sessionのuser / tenant / deviceとlocal crypto identityを照合する。
- 同期runとinitial backfillへ同じimmutable `ActiveSyncContext`を渡す。
- credential、account binding、corruption、stale epoch、invalid grant、
  clock skew、busy / lease / upgradeのstate matrixと回帰testを追加する。
- remote credentialの欠落・破損がlocal cryptoを使うoffline mutationを遮断しない。
- frontend-neutral `ClientError`へreauth / retry / fatal localを区別できる分類を残す。

### やらないこと

- DB / server / wire schema、暗号suite、鍵形式、E2EE envelopeの変更。
- FRBの`Result<T, String>`をtyped error DTOへ変更すること。
  これはIssue #65のbridge / Flutter error transportで行い、Issue #54のUI受入条件は
  その統合完了まで閉じない。
- UI文言、ARB、Dart provider、CLI / MCP transportの変更。
- profile coordinationのlock hierarchy、lease schema、fencing token契約の変更。
- 新規package / crateの追加。

## 5. 実装手順

1. credential kindとlocal crypto状態からaccount readinessを決めるstate matrixを固定する。
2. local cryptoをremote credentialから独立して復元する。cold / changed-generationの
   remote sessionはlocal変数へ解決し、identity検証成功後にsessionと
   credential generationを同じaccount mutex区間で公開する。
3. `active_sync_context`の`Option`をtyped readinessへ置換する。
4. sync status / sync nowは`LoggedOut`だけを成功no-opとし、credential / local crypto /
   corruption failureを`ClientError`として返す。
5. 1回解決したcontextをlease取得、token refresh、backfill、push / pullへ渡す。
6. clock skew、upgrade、profile / database busy、sync lease busy / lostの分類を回帰testで固定する。
7. focused testからworkspace品質ゲートへ進み、別セッションまたは人間が独立検証する。
